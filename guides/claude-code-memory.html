Claude Code 记忆管理：CLAUDE.md 怎么写，AI 才能记住你的项目规范

发布于 2026-10-24进阶Claude CodeCLAUDE.md记忆管理项目规范AGENTS.md

Claude Code 有个让人抓狂的特点：每次开新会话，它都是从零开始。你上次告诉它的构建命令、代码规范、架构决策，重启之后全忘了。CLAUDE.md 就是解决这个问题的：一个放在项目里的记忆文件，Claude 每次开局自动读一遍，等于每次都有个老员工在旁边提醒它。

跟你有啥关系：我试了一下，写好 CLAUDE.md 之后，Claude 第一次给出的代码就很少踩项目规范的坑，不用我每句话都重复"别用默认导出""跑测试用这个命令"。省下来的纠正时间，比写这个文件的时间多得多。

CLAUDE.md 是什么

跟你有啥关系：简单说，CLAUDE.md 是 Claude Code 在每次会话开始时自动加载的 Markdown 记忆文件。你可以把它理解成给 Claude 的入职手册：这个项目是干嘛的、用什么技术、命令有哪些、规矩有哪些、哪些地方不能碰。

Claude Code 读 CLAUDE.md 有个层级结构，从宽泛到具体依次加载：

层级 位置 作用
组织级 macOS 是 /Library/Application Support/ClaudeCode/CLAUDE.md，Linux 是 /etc/claude-code/CLAUDE.md 公司统一规定，个人改不了
项目级 项目根目录的 ./CLAUDE.md 或 ./.claude/CLAUDE.md 团队共享，提交到 git，这是最主要的一层
用户级 ~/.claude/CLAUDE.md 你个人的跨项目偏好
本地级 项目里的 ./CLAUDE.local.md 你个人在这个项目的笔记，不提交到 git

这几层是拼接起来一起读的，不是互相覆盖。越靠近你当前工作目录的文件越后读，等于优先级越高。嵌套目录里的 CLAUDE.md 也会叠加上去：在子目录里工作时，那个子目录的 CLAUDE.md 会额外加载。

还有一个新约定：现在很多工具都认 AGENTS.md 这个文件名（Claude Code、Cursor、Codex 都认）。如果你已经有 AGENTS.md，可以让 CLAUDE.md import 它，或者直接把 CLAUDE.md 做成 AGENTS.md 的软链接，这样一套文件多处通用。

CLAUDE.md 怎么生成：先跑 /init

跟你有啥关系：不用从空白开始写，让 Claude 自己先起草一份，你再改。

在项目根目录跑：

claude
/init

/init 会分析你的代码库，自动生成一份初始 CLAUDE.md，里面包括它发现的构建命令、测试方式、项目结构、常见约定。我试过，生成的草稿大概能覆盖 70% 的内容，剩下 30% 是你才知道的规矩——比如"这个目录是生成的别改""那个接口有坑别碰"——需要你手动补。

还有一个更顺手的方法：工作过程中随时用 # 开头写一句话，Claude 会把这句话写进相关的 CLAUDE.md。比如你说：

# 这个项目用 pnpm，不要用 npm

Claude 就会把这条记下来。记忆就是这样一点点长出来的，不用专门抽时间写。

CLAUDE.md 写法：放什么

跟你有啥关系：这部分是全文最值钱的，直接照着写就行。

Anthropic 官方的建议是：一个 CLAUDE.md 里放 10 条左右的要点就够了。下面是我按重要性排的清单：

1. 这个项目是干嘛的

一句话说清楚，别让 Claude 猜：

# 项目说明
这是一个 Vite + React 的单页应用，给用户做 YouTube 数据分析，不是 Next.js 项目。

2. 常用命令

把真正会用的命令列出来，别列一堆用不上的：

## 常用命令
- `npm run dev`：启动开发服务器（Vite）
- `npm run build`：类型检查 + 生产构建
- `npm run typecheck`：跑 tsc --noEmit
- `npm run lint`：跑 ESLint
- `npm run test`：跑 Vitest 测试

3. 技术栈

写清楚版本和关键选择，尤其是那些容易搞错的：

## 技术栈
- React 19 + TypeScript（严格模式）
- Vite（不是 Next.js App Router）
- TanStack Query v5（服务端状态管理）
- CSS Modules（每个组件配一个同名 .css 文件）

4. 项目结构

告诉 Claude 代码都在哪，省得它每次都要找：

## 项目结构
- src/api/：YouTube API 客户端和原始类型
- src/components/：UI 组件，每个配一个同名 .css 文件
- src/hooks/：自定义 Hook（数据获取走 TanStack Query）
- src/lib/：纯工具函数
- src/types.ts：共享类型

5. 先读哪几个文件

给 Claude 指路，告诉它上手先看哪 3-6 个文件：

## 先读这些
- README.md：项目总览
- src/App.tsx：入口和路由
- src/lib/api.ts：核心数据流

6. 硬约束

那些绝对不能违反的规矩，写清楚：

## 硬约束
- 不要提交任何密钥或 token
- 不要跳过无障碍属性（a11y）
- 不要用默认导出，全部用命名导出
- 不要创建过多的注释，代码自解释优先

7. 容易踩的坑

项目特有的陷阱，别人不知道、只有你知道的：

## 注意
- src/generated/ 是自动生成的，不要手动改
- 那个旧的 auth 模块不要动，等下个版本统一重构
- 数据库迁移必须先在 staging 跑一遍

8. 怎么验证改动

告诉 Claude 改完之后要怎么检查：

## 验证
- 改完先跑 `npm run typecheck`，再跑 `npm run test`
- 有 UI 改动要截图确认

CLAUDE.md 写法：不放什么

跟你有啥关系：写错东西比不写更糟，这几类千万别放。

  • 长篇 onboarding 文档：几百行的入职手册不要塞进来，Claude 读不完也记不住。放到 docs/ 里，需要的时候用 @docs/文件名.md 引用。
  • 完整风格指南：几十页的 style guide 也不要，提炼成 5-10 条最关键的就行。
  • 密钥和 token：绝对不要。CLAUDE.md 是要提交到 git 的，写密钥等于公开。
  • 空话： "写高质量代码""要 helpful"这种话没用，Claude 不知道什么叫高质量。改成可验证的具体指令："用 2 空格缩进"比"格式要规范"有用 10 倍。
  • 过时的内容：项目变了，CLAUDE.md 没跟着变，比没有更糟。每次改架构、换命令、改规范，顺手更新一下。

CLAUDE.md 的 200 行红线

跟你有啥关系：这是 Anthropic 官方明确给的数字，超过就适得其反。

官方文档原话：每个 CLAUDE.md 文件目标控制在 200 行以内。更长的文档会消耗更多上下文，还会降低 Claude 遵守指令的概率。Anthropic 自己的实验也证实：臃肿的记忆文件会让 Claude 忽略你真正的指令。

我自己的经验是：40-60 行的紧凑文件效果最好。Karpathy 公开的那份 CLAUDE.md 就是 60 行左右的规模，这就是正确的体量感。项目特有的细节（构建命令、测试方式、命名规范）是在这个基础之上加，但整个文件栈加起来最好也别超过 200 行。

如果你的 CLAUDE.md 已经写到 300 行了，说明该拆了：把主题性的内容移到 docs/ 或 .claude/rules/ 里，CLAUDE.md 里只留最核心的、每次会话都需要的东西，需要的时候再引用。

CLAUDE.md 的常见错误

跟你有啥关系：这几个错我都犯过，提前告诉你。

错误一：写得太长

300 行的 CLAUDE.md，Claude 根本记不住前面的内容。解决办法：砍到 200 行以内，细节移到别的文件里引用。

错误二：写得太模糊

"注意代码质量""保持一致性"——这种话 Claude 没法执行。改成"用 2 空格缩进""组件用命名导出""API 错误必须返回标准错误对象"，具体、可验证。

错误三：从来不更新

项目从 Vite 迁到 Next.js 了，CLAUDE.md 还写着 Vite。Claude 按旧的来，你还得纠正它。解决办法：每次改架构、换工具链，顺手更新 CLAUDE.md，养成习惯。

错误四：把 CLAUDE.md 当权限控制

写"不要读 .env 文件""不要碰生产配置"在 CLAUDE.md 里，Claude 会尽量遵守，但这不是强制的。真正要 enforcement，得用 permissions.deny、hooks、CI 检查这些机制。CLAUDE.md 是提醒，不是锁。

错误五：每个项目复制粘贴同一份

跨项目的通用偏好（比如你的代码风格、常用工具）应该放 ~/.claude/CLAUDE.md，项目特有的才放项目级。每个项目都贴同一份大文件，改一个地方要改十个地方，迟早会不一致。

一套可落地的记忆管理流程

跟你有啥关系：直接抄这个流程，不用自己设计。

  1. 新项目：跑 /init 生成草稿，手动补上项目特有的规矩和坑，控制在 100 行以内
  2. 日常：工作时用 # 随手记，Claude 自动帮你写进 CLAUDE.md
  3. 每周：花 5 分钟看一眼 CLAUDE.md，删掉过时的、合并重复的
  4. 每月：跑 /memory 打开记忆文件检查一遍，看看 Claude 自己记了什么有没有错的，错的删掉
  5. 换项目：新项目先看一眼 ~/.claude/CLAUDE.md，确认通用偏好还在，再写项目级的

我的 verdict

跟你有啥关系：CLAUDE.md 是 Claude Code 投入产出比最高的一个文件。花 30 分钟写一份 60 行左右的、具体的、可验证的记忆文件，之后每个会话都能省下大量重复纠正的时间。

记住三个数字：200 行是红线，60 行是甜点，10 条是要点。写得短、写得具体、定期更新，比写得长、写得全、写完不管有用得多。
