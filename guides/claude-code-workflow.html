Claude Code 高效工作流：从安装到第一个 PR

发布于 2026-10-24新手Claude CodeAI 编程终端工作流

Claude Code 是 Anthropic 官方出的终端 Agent，跟聊天助手不一样：它直接读你的仓库、改文件、跑命令，任务做完才停手。

跟你有啥关系：如果你每天在终端里写代码，Claude Code 能把「改代码 → 跑测试 → 提 PR」这条链路串起来，省掉大量机械活。这篇从零开始，装完就能交出第一个 PR。

Claude Code 怎么安装

跟你有啥关系：装错方式后面全是版本问题，直接用官方推荐的原生安装器，别绕路。

macOS / Linux / WSL：

curl -fsSL https://claude.ai/install.sh | bash

Windows PowerShell：

irm https://claude.ai/install.ps1 | iex

备选方式（也都可用）：

# Homebrew（macOS）
brew install --cask claude-code
# npm（需要 Node.js 18 以上）
npm install -g @anthropic-ai/claude-code

我试了一下，原生安装器最省心，自带自动更新。npm 方式能用，但你的 Node 版本一变就可能出幺蛾子，团队协作时尤其容易出现「我这能跑你那不行」。

装完验证一下：

claude --version

如果报 command not found，原生安装器是把二进制放到了 ~/.local/bin/claude，把这个目录加进 PATH 再重开终端：

export PATH="$PATH:$HOME/.local/bin"

Claude Code 怎么登录

跟你有啥关系：登录方式决定你按什么付费，选错了后面改起来麻烦。

进你的项目目录再启动，千万别在 home 目录启动——Claude Code 会把启动目录当成项目根，记忆和配置都按这个目录来：

cd your-project
claude

第一次运行会让你登录，二选一：

  1. 订阅登录：用 Claude 订阅账号（Pro、Max、Team）在浏览器里 OAuth 一下，适合已经订阅的人。
  2. API Key：用 Anthropic Console 的 Key，设置环境变量 ANTHROPIC_API_KEY，按量付费，适合走 API 额度的场景。

一个坑：如果登录后报 400 "organization disabled"，八成是环境里有个旧的 ANTHROPIC_API_KEY 在捣乱，把它 unset 掉、重开终端再试。会话里用 /status 能确认当前用的是哪种认证。

SSH 远程机器上登录时，浏览器打不开怎么办？在登录提示处按 c，它会把认证链接复制出来，你在本地浏览器打开、把码贴回终端就行。

Claude Code CLAUDE.md 怎么配置

跟你有啥关系：不做这步，Claude Code 每次都要重新猜你的项目结构，改出来的代码风格也飘忽不定。

/init 生成 CLAUDE.md

进项目后先跑：

/init

它会扫描仓库，生成一个 CLAUDE.md 文件。这就是项目的「说明书」，Claude Code 每次会话开始都会先读它。生成后你自己再改一改，补上这些：

# 项目名：一句话说清这项目是干嘛的

## 结构
- backend/routes/ — 接口层
- backend/models/ — 数据模型
- frontend/components/ — React 组件

## 命令
- 启动后端：cd backend && uvicorn main:app --reload
- 启动前端：cd frontend && npm run dev
- 跑测试：cd backend && pytest

## 规范
- 后端照着 routes/todos.py 的写法来
- 新接口必须补测试
- 前端用 Tailwind，导航改动同步改 Sidebar

我试了一下，CLAUDE.md 写得越具体，Claude Code 第一次输出就能用的概率越高。只写一句「这是一个 Web 项目」等于没写。

会话里的记忆技巧

  • # 开头的内容会持久化进 CLAUDE.md，适合记录高价值约定。
  • 会话长了（20-30 轮之后）跑一次 /compact，把上下文压缩一下再继续，省 token 也省钱。
  • 换任务时跑 /clear，别让上一个任务的上下文污染下一个任务。

Claude Code 第一个任务流程

跟你有啥关系：直接丢一句「帮我加个功能」效果最差，照下面这个顺序，成功率会高很多。

1. 先规划，再动手

多文件任务、涉及架构的任务，先进规划模式：

/plan
给 /api/todos 接口加分页

规划模式下 Claude Code 只读不写，先把你的现有分页写法翻出来，给你一个方案，你点头了它再动手。我试了一下，这一步能省掉至少一半返工——它不会再凭空发明一套你项目里没有的写法。

2. 提需求要具体

差的说法：

帮我把后端改一下

好的说法：

在 backend/routes/todos.py 里，给 /api/todos 加分页参数 page 和 page_size，照着 routes/users.py 已有的分页写法来，返回里带 total 字段，补一个测试。

三要素：文件指名、参照现有写法、验收标准。缺一个，输出质量就掉一档。

3. 让它自己验证

任务描述里直接加上验证要求：

改完跑 pytest，全部通过才算完。

Claude Code 会自己跑测试、看报错、修代码、再跑，形成闭环。你不用在旁边当监工，只需要最后看一眼 diff。

4. 检查 diff，提 PR

改完先看 diff：

/diff

确认没问题，再让它提 PR：

/commit

/commit 会按暂存区的改动生成提交信息。PR 同理，用 /pr 可以直接生成带描述的 Pull Request。我的习惯是：提交前一定先跑一遍 /review，让它自己检查一遍 diff——leftover 的 debug 输出、半截重命名、被偷偷删掉的测试，这些低级问题基本能在这步拦住。

Claude Code 实战例子：完整走一遍加接口

跟你有啥关系：上面讲的是流程，这个例子是流程跑起来到底长什么样，照着敲一遍就全懂了。

假设你要给一个 FastAPI 项目的 todos 接口加分页，实际对话大概是这样的：

/plan
给 /api/todos 加分页，参数 page 和 page_size，返回里带 total

Claude Code 先读 routes/todos.py 和 routes/users.py（后者已经有分页写法），给出方案：照 users 的写法来，todos 复用同一套参数解析和返回格式。你确认方案没问题，接着说：

按这个方案改，改完跑 pytest，全部通过才算完

它开始改文件：routes/todos.py 加参数、models 层不动、tests/test_todos.py 补两个用例（正常分页和越界页码）。改完自己跑 pytest，第一次报了个导入错误，它自己定位到是测试文件里 mock 路径写错了，修掉再跑，全部通过。

最后你检查：

/diff
/review

diff 里只有三个文件，改动干净，review 没报问题。提交：

/commit

提交信息它已经按暂存区改动生成好了，你看一眼没问题就确认。整个过程你敲的命令不到十条，大部分时间花在看 diff 和确认方案上，而不是写代码。

这个例子里有三个关键点值得复盘：第一，/plan 让方案先对齐，避免改完返工；第二，「改完跑 pytest」这句验证要求让它形成了自验证闭环；第三，/diff + /review 是你最后的质量关，别跳过。流程跑熟之后，日常加接口、修 bug、补测试基本都是这个套路换个任务描述。

Claude Code 常用命令速查

跟你有啥关系：记住这十几个，日常 90% 的场景够用了。

命令 干嘛
/help 看所有命令
/init 生成 CLAUDE.md
/plan 规划模式，只读不写
/clear 清空对话，换任务
/compact 压缩上下文，省 token
/diff 看当前改动
/review 检查改动里的 bug
/commit 生成提交信息并提交
/pr 创建 Pull Request
/model 切换模型
/permissions 看当前工具权限
/status 看会话与认证状态
/memory 查看/编辑 CLAUDE.md
/config 看当前配置

快捷键也记两个：Ctrl+L 清屏（不丢上下文），Esc Esc 回到上一条消息重写。

Claude Code 避坑清单

跟你有啥关系：这些坑我基本都踩过一遍，提前避开能省一下午。

  1. 别在 home 目录启动。项目记忆会错乱，换到项目目录重开。
  2. 别用 --dangerously-skip-permissions。这个参数会跳过所有权限确认，只适合放在没联网的容器里用，生产机器上用等于裸奔。
  3. 别一次丢巨型任务。一个任务只做一件事，拆小了成功率才高。 mega-prompt 换来的往往是 mega-返工。
  4. 别让它猜你的规范。CLAUDE.md 里写清楚命令、目录、写法，猜错的成本比写文档高得多。
  5. 长会话不 compact。上下文一满，它就开始「失忆」，前面的约定全忘光。

我的 verdict

Claude Code 值不值得装？如果你每天在终端写代码，值得。安装 5 分钟，/init 生成 CLAUDE.md 再花 10 分钟改一改，第一个任务照「先规划、再具体提、让它自验证、最后 review 提 PR」这个流程走，基本一次就能跑通。

关键就一句话：把它当成一个需要说明书的新同事，而不是一个会读心的聊天框。说明书（CLAUDE.md）写得越好，它干活越靠谱。
