Claude Code + MCP：接数据库、接 API，让 Claude 能动手干活

发布于 2026-10-24进阶Claude CodeMCP数据库API配置

Claude Code 本身只能读写文件、跑命令。但很多真实任务需要它去查数据库、调 API、翻 GitHub、搜文档——这些它本来做不到。MCP（Model Context Protocol）就是给它接外设的插口。

跟你有啥关系：配好 MCP 之后，你可以直接跟 Claude 说"查一下 users 表里昨天注册的用户""去 GitHub 上看看那个 issue 的最新评论"，它真的会去查、去调，而不是让你先把数据复制粘贴给它。我试了一下，配好数据库 MCP 之后，查数据、写报表这类活，基本不用我手动导数据了。

MCP 是什么

跟你有啥关系：一句话，MCP 是 Anthropic 定的开放协议，让 AI 工具能以统一的方式调用外部服务。你可以把它理解成"AI 的 USB 接口"：数据库、API、文件系统、浏览器，每个服务只要提供一个 MCP 服务器，Claude Code 就能插上去用。

MCP 服务器有两种连接方式：

  • stdio：本地启动一个进程，通过标准输入输出通信。适合本地工具，比如数据库、本地文件。
  • HTTP：通过网址连接远程服务。适合云端 API，比如 GitHub、Notion、第三方服务。

你不用深究协议细节，会配就行。

Claude Code MCP 配置：三种位置

跟你有啥关系：配错位置是新手最常见的坑，先把这个搞清楚。

Claude Code 读 MCP 配置有三个位置：

位置 文件 适用范围
项目级 项目根目录的 .mcp.json 整个团队共享，适合数据库、内部 API 这种团队都要用的服务
用户级 ~/.claude.json（注意不是 ~/.claude/claude.json） 只对你个人生效，所有项目都能用
设置文件 .claude/settings.json 里的 mcpServers 字段 也可以放，但一般用前两个就够了

优先级是项目级 > 用户级。团队共享的服务放项目级（可以提交到 git），你个人用的工具放用户级。

一个容易踩的坑：~/.claude.json 是家目录下的一个文件，不是 ~/.claude/ 目录里的文件。我第一次配的时候就找错了地方，浪费了半小时。

MCP 服务器怎么配置：两种方法

跟你有啥关系：有命令行和手写配置文件两种路子，命令行快，配置文件灵活。

方法一：claude mcp add 命令（推荐新手）

最快的方式是直接用命令加：

# 加一个 stdio 服务器（本地数据库）
claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres

# 加一个 HTTP 服务器（远程 API）
claude mcp add github --transport http https://mcp.github.com

# 指定作用域：user 是全局，project 是项目级
claude mcp add github --scope user --transport http https://mcp.github.com

作用域的 --scope 有三个值：local（默认，只对你、只在当前项目）、project（写进 .mcp.json，团队共享）、user（全局，所有项目）。注意一个反直觉的点：local 指的是作用域，不是文件位置，local 的服务器其实也存在 ~/.claude.json 里。

加完之后用 claude mcp list 看一眼，确认服务器状态是正常，不是 Pending approval。项目级的 .mcp.json 服务器第一次运行时，Claude Code 会让你确认批准，批准之后才能用。

方法二：手写 .mcp.json

想精细控制，就直接写配置文件。项目根目录建一个 .mcp.json：

{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://mcp.github.com",
      "headers": {
        "Authorization": "Bearer ${GITHUB_TOKEN}"
      }
    },
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/you/projects"],
      "env": {}
    },
    "postgres": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "POSTGRES_CONNECTION_STRING": "${DATABASE_URL}"
      }
    }
  }
}

关键规矩：密钥永远用 ${变量名} 引用环境变量，不要直接写进配置文件。.mcp.json 是要提交到 git 的，硬编码 token 等于把钥匙贴在门口。我试过一次差点把 token 提交上去，幸好提交前检查了一眼。

实战一：接数据库

跟你有啥关系：这是最常见的 MCP 用法，查数据不用再手动导 CSV 了。

以 PostgreSQL 为例，先装服务器：

npx -y @modelcontextprotocol/server-postgres

然后在 .mcp.json 里配好连接串（用环境变量）：

{
  "mcpServers": {
    "postgres": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "POSTGRES_CONNECTION_STRING": "${DATABASE_URL}"
      }
    }
  }
}

配好之后，在 Claude Code 里直接说：

查一下 users 表，昨天注册的用户有多少，按渠道分组

Claude 会通过 MCP 调数据库，跑查询，把结果拿回来分析。你还可以接着说"把这个结果写成一份日报"，它能一口气做完。

但要注意权限：给 MCP 的数据库账号只给只读权限，别给写权限。不然 Claude 一个手滑 DELETE 错了表，你哭都来不及。我自己的做法是专门建一个只读账号给 MCP 用，写操作一律我手动来。

实战二：接 API 和第三方服务

跟你有啥关系：GitHub、Notion、Slack 这些服务都有现成的 MCP 服务器，接上就能用。

以 GitHub 为例：

claude mcp add github --transport http https://mcp.github.com

接上之后，你可以说：

看看我那个仓库最新 open 的 issue，有没有带 bug 标签的
帮我把这个 PR 的评论整理成一份摘要

Claude 会去调 GitHub API，把 issue、评论拉回来。比你自己一个个点开看快得多。

常用的现成 MCP 服务器还有：

服务 用途
filesystem 让 Claude 访问指定目录之外的文件
postgres / sqlite 查数据库
github 查 issue、PR、评论
brave-search 联网搜索
playwright 操作浏览器、做自动化

找服务器有个好去处：去搜 MCP 服务器目录，或者直接问 Claude"有没有 XX 服务的 MCP 服务器"，它一般能给你指路。

实战三：让 Claude 在脚本里用 MCP

跟你有啥关系：不只是交互式对话，写脚本、跑 CI 的时候也能用 MCP。

非交互模式下，用 --mcp-config 指定配置文件，用 --allowedTools 放行 MCP 工具：

claude -p "查一下数据库里订单量最大的前 10 个用户" \
  --mcp-config ./.mcp.json \
  --allowedTools "mcp__postgres__*"

工具名的格式是 mcp__服务器名__工具名，比如 mcp__postgres__query。用通配符 mcp__postgres__* 就是放行这个服务器的全部工具。

CI 里用的时候注意：密钥要放在 CI 的 secrets 里，通过环境变量传进去，不要写进配置文件。这个前面说过，再强调一次。

MCP 配置的 5 个避坑清单

跟你有啥关系：这几个坑我都踩过，提前告诉你能省不少时间。

1. 密钥不要硬编码

前面说过，用 ${变量名}。提交前用 git diff 检查一遍，确认没有 token 混进去。

2. 项目级服务器要先批准

.mcp.json 里的服务器第一次运行时，Claude Code 会问你要不要批准，批准之前 claude mcp list 里显示的是 Pending approval。别以为配完就能直接用，先跑一次批准。

3. 路径要用绝对路径或相对项目根目录

stdio 服务器的命令参数里如果涉及文件路径，Claude Code 是相对于 .mcp.json 所在位置解析的。写相对路径没问题，但要确认是相对于项目根目录，不是相对于你当前终端的目录。

4. 别给 MCP 太大权限

数据库只读、文件系统只限定在项目目录、API token 只给最小权限。MCP 是给 Claude 开的口子，口子越大，误操作的风险越大。

5. 服务器挂了先看日志

某个 MCP 工具突然不能用了，先跑 claude mcp list 看状态，再检查服务器进程是不是挂了、环境变量是不是没传进去。大多数问题都是环境变量没设置或者命令写错了，不是 MCP 本身的问题。

我的 verdict

跟你有啥关系：MCP 是 Claude Code 从"能写代码"到"能干活"的关键一步。先从一个最痛的场景开始——对我来说是查数据库——配一个服务器跑通，尝到甜头之后，再慢慢往上加。

别一上来配十个服务器，先把一个用熟，权限收紧，再扩展。MCP 配得好，Claude 就像多了几双手；配得糙，就是给自己埋雷。
