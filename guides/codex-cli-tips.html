Codex CLI 实战：终端里用 AI 写代码的 10 个技巧

发布于 2026-10-24进阶CodexOpenAICLI终端技巧

Codex CLI 是 OpenAI 的终端 Agent：进项目目录、敲 codex，它就能读仓库、改文件、跑测试。我用了一段时间，总结出 10 个真正提效的技巧，个个都能直接抄。

跟你有啥关系：如果你已经装了 Codex 但只会打字聊天，那等于只用了它 30% 的能力。下面这些才是拉开差距的地方。

Codex CLI 怎么安装

# macOS / Linux
curl -fsSL https://chatgpt.com/codex/install.sh | sh
# npm
npm install -g @openai/codex
# Homebrew（macOS）
brew install --cask codex

装完验证：

codex --version
codex update

进项目目录启动：

cd /path/to/your-project
codex

第一次启动会走登录流程。装完如果 codex 指向了旧版本，先查一下 PATH 里到底是哪个在生效：

command -v codex
type -a codex

Codex CLI 交互模式和 exec 模式的区别

跟你有啥关系：用错模式，简单任务变复杂，复杂任务变失控。

Codex 其实是两种工具：

# 交互模式：持续会话，上下文一直都在
codex

# 非交互模式：跑完一个任务就退出，适合脚本和 CI
codex exec "给 auth 模块加错误处理"

我的分法：

  • 交互模式：要连续干好几件事——先看结构、再加缓存、再写测试、再跑测试修 bug，全程一个会话，Codex 越用越懂你的项目。
  • exec 模式：一次性任务、自动化脚本、CI 里跑。比如 nightly 跑一遍「检查所有 TODO 是不是都过期了」，exec 完就退出，干净利落。

新手最常见的错误就是拿交互模式当一次性问答用，每次新开会话，上下文全丢，Codex 永远是「第一天上班」的状态。

Codex CLI 开局配置：先跑这五个命令

跟你有啥关系：第一次进一个仓库，先把这五个命令跑一遍，后面所有任务都顺。

进交互界面后，依次敲：

/init
/permissions
/mcp
/skills
/hooks
  • /init：生成 AGENTS.md，这是 Codex 的项目记忆文件，地位等于 Claude Code 的 CLAUDE.md。生成后自己再改改，补上项目结构、常用命令、代码规范。
  • /permissions：设审批策略。Auto 是自动放行，Read Only 是只读，生产仓库建议先用保守的，等熟了再放开。
  • /mcp：看接了哪些 MCP 工具服务器。
  • /skills：看有哪些技能可用。
  • /hooks：看生命周期钩子。

我试了一下，开局五连花不了 2 分钟，但能避免后面一堆「它怎么改了不该改的文件」之类的问题。

Codex CLI @ 引用文件技巧

跟你有啥关系：你说「那个支付模块」，Codex 要猜半天；你直接 @ 出来，它立刻定位。

在交互界面里：

@ + 文件名模糊搜索，Tab 或回车插入路径

比如：

照着 @src/lib/stripe/webhooks.ts 的写法，给 @src/lib/paypal/webhooks.ts 加签名校验

文件指名 + 参照写法，输出质量直接上一个档次。跟 Claude Code 那套「具体文件 + 参照模式」是一个道理，所有 Agent 都吃这一套。

Codex CLI ! 直接跑 shell 命令

跟你有啥关系：终端党最烦的就是在 AI 对话和 shell 之间来回切，Codex 让你不用切。

在 Codex 界面里，! 开头就是本地 shell 命令：

!npm test
!git status
!ls src/

不用退出 Codex、不用另开终端。查个测试结果、看个文件列表，随手就办了。

Codex CLI Tab 排队和 Enter 插话技巧

跟你有啥关系：Codex 跑长任务时，你想起个补充要求，不用等它跑完，也不用打断它。

  • Codex 运行时按 Enter：把新指令插进当前这一轮。
  • Codex 运行时按 Tab：把指令排队到下一轮。
  • Ctrl+G：在外部编辑器里写长提示，适合那种几百字的需求描述。
  • Ctrl+L：只清屏，不丢上下文。
  • Esc 按两下（输入框为空时）：回到上一条消息改写，继续按会一路往前翻，改完回车就从那个点分叉重跑。

我试了一下，Tab 排队这个最实用：长任务跑到一半想起「哦对还要补个测试」，Tab 一下敲进去，不用等、不用打断，任务跑完自动接上。

Codex CLI 会话管理命令

跟你有啥关系：上下文一满就开始「失忆」，会话管理不好，前面白干。

命令 干嘛
/status 看 token 用量、会话状态
/compact 压缩对话，释放上下文
/clear 清空对话，换新任务
/resume 恢复之前的会话
codex resume --last 命令行直接恢复最近一次会话

我的节奏：一个任务一个会话，任务结束 /clear；长任务中途 /status 看一眼 token，快满了就 /compact；昨天没干完的活今天用 codex resume --last 接着干。

Codex CLI 并行探索：/fork 和 /side

跟你有啥关系：想同时试两个方案，又不想污染主线会话，这两个命令就是干这个的。

  • /fork：从当前点开一个新分支会话，主线不受影响。
  • /side：开一个临时探索会话，用完即弃，适合「先看一眼这个思路行不行」。
  • /agent：切换子 Agent，让不同 Agent 分工。

举个例子：重构方案 A 和 B 拿不准，主线继续走 A，/fork 一个分支试 B，最后哪个效果好留哪个，另一个直接丢掉，不用来回撤销。

Codex CLI 提 PR 前的检查流程

跟你有啥关系：Agent 改完的代码直接提 PR，等于把 review 的活推给同事。自己先过一遍，口碑好很多。

 /diff     # 看改了哪些文件
 /review   # 让 Codex 自己审一遍

/review 会从审稿人视角看你的改动：有没有漏掉的边界情况、有没有不一致的命名、有没有被顺手删掉的测试。我试了一下，它自己审出来的低级问题，比同事在 PR 里指出来体面得多。

流程固定下来：

改完 → /diff → /review → 修掉 review 提的问题 → /diff 再确认 → 提 PR

Codex CLI 沙箱和权限设置

跟你有啥关系：个人小项目和生产仓库，权限策略不能一样，图省事全开 Auto 迟早出事。

Codex 的权限策略在 /permissions 里设，思路是：

  • 个人练手项目：Auto 全开，跑得最顺。
  • 团队协作仓库：默认审批，写文件和跑命令前确认一下，读文件放行。
  • 生产相关仓库：Read Only 起步，确认没问题再逐步放开写权限。

还有个 --sandbox 参数，命令行启动时可以指定沙箱级别，配合 --full-auto（只在失败时才问你）用在可信的自动化场景里。

一句话：权限不是越松越好，是跟仓库的重要性匹配才好。

Codex CLI exec 自动化技巧

跟你有啥关系：有些活不需要人盯着，让它夜里自己跑，早上起来收结果。

codex exec 的真正价值在自动化：

# 每夜跑一遍：检查过期 TODO
codex exec "扫描全仓库的 TODO 注释，列出超过 30 天没动的，输出成报告"

# CI 里跑：生成改动摘要
codex exec "总结这次提交的改动，写一段 changelog"

# 批量任务：给每个模块补测试骨架
codex exec "给 src/services/ 下每个没有测试文件的模块生成测试骨架，不改业务代码"

配合 cron 或 CI 定时跑，等于雇了个不用睡觉的初级工程师。注意 exec 模式跑完就退出，上下文不保留，所以任务描述要写完整，别指望它记得上次的会话。

我的 verdict

Codex CLI 最值得练的就三样：模式分清（交互 vs exec）、引用精准（@ 文件）、会话管好（/compact、/clear、/resume）。这三样到位了，剩下的技巧都是锦上添花。

终端党记住一句话：别把 Codex 当聊天框，把它当成一个能跑命令、能改文件、能自己验证的同事，任务描述越具体、验收标准越清楚，它回馈你的质量越高。

命令与功能截至 2026 年 10 月撰写时，以 OpenAI Codex 官方文档为准，版本更新后个别命令可能有变。
