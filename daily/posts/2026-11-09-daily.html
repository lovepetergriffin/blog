Claude Code"别再问我"按一下，密钥就进了公开仓库：1,122 个仓库还在裸奔

跟你有啥关系：如果你用 Claude Code 写代码，点过一次"Yes, and don't ask again"，那条带密钥的命令可能正躺在你仓库的 .claude/settings.local.json 里——公开仓库的话全世界都能看。安全公司 Apiiro 11 月 5 日公布的扫描结果：公开 GitHub 上有 104,185 份这个文件，其中 1,122 份（约 1.1%）含真实密钥，共 1,379 个不同密钥；算上 git 历史、共享配置文件和 agent 聊天记录，总数是 2,539 个密钥、1,994 个仓库。超过三分之一能直接连数据库（379 个数据库密码、122 个 Supabase service-role key），还有 43 个 SSH 登录、42 个 GitHub/GitLab/npm token、23 个 AWS key；63 家机构中招。更扎心的是：Claude Code 只把这个文件加进你本机的全局 gitignore，不写进项目 .gitignore；539 个仓库里还是 Claude 自己联名提交了这个文件。Apiiro 没有实测这些密钥是否还有效，但已有一家被通知的公司确认自己的 key 还活着。我的判断：这不是 prompt 注入，是日常操作踩的坑——今天就去查一遍自己的仓库，教程在文末。原文链接

ChatGPT Dots 会替你去邮箱取登录码了，但输码那一下它自己先怂了

跟你有啥关系：如果你是 ChatGPT Pro 或 Business Premium 用户，你的 Dot 现在能帮你跑完"注册—收验证码—登录"的全套流程，不用你切窗口翻邮箱。11 月 7 日的消息：Dots 能从已连接的邮箱里取注册/登录验证码，替你完成 2FA；前提是你先授权，方式是一次授权或始终允许。Dots 9 月 29 日 DevDay 发布，跑在 GPT-6 Astra 上，各自带独立云电脑和浏览器，能接 4,000 多个应用的插件。早期用户的反馈很有意思：Dot 看得到验证码，轮到输入那一下却会犹豫——内置安全规则卡住了，高风险操作（确认交易、改敏感数据）本来就被禁。我的判断：登录这种"替我点一下"的活交给 agent 是迟早的事，但 2FA 的意义就是"证明是你本人"，让 agent 代劳等于把这道关也交了出去——先拿不重要的账号试，别一上来就接主力邮箱。原文链接

🎓 3 分钟小教程：给 Claude Code 上锁，别让它再把密钥写进公开仓库

前置条件：在用 Claude Code，有 git 仓库；装 gitleaks（brew install gitleaks，Windows 用 winget install gitleaks）。

  1. 先查自己有没有中招：仓库根目录跑 git ls-files .claude/，如果 settings.local.json 在列表里，说明它已被追踪——立刻 git rm --cached .claude/settings.local.json 取消追踪。
  2. 项目级上锁：在项目根目录的 .gitignore 里加一行 .claude/settings.local.json。Claude Code 只会把它写进你本机的全局 gitignore，换台电脑、换个协作者就失效，项目级 .gitignore 才是真保险。
  3. 扫一遍历史：跑 gitleaks detect --verbose，把整个仓库历史扫一遍；扫出密钥先轮换再删文件——光删文件没用，密钥还躺在 git 历史里。
  4. 治本：以后别在命令行里直接贴密钥，改走环境变量或 .env 文件；再给 Claude Code 的 Bash 权限加一条 deny 规则，含 token=、password= 的命令一律先问你。

预期效果：settings.local.json 再也不会进仓库；历史里埋过的旧密钥也被扫出来轮换掉。提醒一句：Apiiro 扫出的 2,539 个密钥里有一半在仓库里躺了 217 天以上——越早查越好。教程参考
